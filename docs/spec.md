# カオス振り子追跡エイムゲーム 仕様書（改訂版）

> 改訂履歴
> - 初版：機能仕様の定義
> - 改訂：claude design からのハンドオフを統合（ハンドオフ側を採用）。ユーザー追加変更を反映。

## 1. プロジェクト概要
カオス振り子（二重または三重振り子）の先端おもりをマウスカーソルで追跡し、追従精度をスコア化するブラウザエイムゲーム。

- プラットフォーム：Webブラウザ（PC、マウス操作前提）
- プレイ時間：1ゲーム60秒
- スコア形式：単一試合での累積スコア（フレーム毎の距離スコアを積算）

## 2. ゲーム仕様

### 2.1 基本ルール
- ゲーム時間：60秒固定
- 操作：マウスカーソルで先端おもりを追跡
- スコア：毎フレーム、カーソルと先端おもりの距離（または直近軌跡への距離）からガウシアンで距離スコアを算出し累積

### 2.2 距離スコアの算出
- **先端追跡スコア（Tip）**：`tipScore = exp(-d² / σ²)`
  - `d` = カーソル位置と先端おもりの距離
  - `σ` = 振り子全長 × **0.06**（仕様初版の 0.12 から半分に変更し、より厳しく）
  - 許容半径：`3σ` を超える距離では `tipScore = 0`（ガウシアンの裾切り）
- **軌跡なぞりスコア（Trail）**：`trailScore = exp(-minD² / σ_t²) × 0.55`
  - `minD` = カーソルから「直近軌跡（=過去 500ms 分の線分列）」への最短距離
  - `σ_t` = `σ × 1.5`（先端より広めの許容）
  - 重み 0.55（先端追跡より弱め）。`3σ_t` を超えたら 0
- **採用スコア**：`score_per_frame = max(tipScore, trailScore)`
- 毎フレーム計算し、累積値を最終スコアとする
- スコア累積式：`scoreAcc += score_per_frame × dt × 100`（dt は描画間隔（秒）。100 はスケール係数）
- 理論最大：60秒 × 100 = **6,000**（PERFECT SCORE）

### 2.3 物理シミュレーション
- 対象：二重振り子（おもり2個）または三重振り子（おもり3個）
- 質量：全おもり同一・固定（カスタムモードでも変更不可）
- 重力加速度：`G = 9.81`
- 減衰：なし（エネルギー保存）
- 数値積分：RK4（4次のルンゲ・クッタ法）+ サブステップ
- 描画フレームレート：60fps（requestAnimationFrame）
- 物理サブステップ数：1描画フレームあたり **8回**（仕様初版の 4–10 範囲内）
- エネルギー保存性能を実装段階で確認（60秒プレイ後の総エネルギー誤差が許容範囲内であること）

### 2.4 フィールド
- 形状：振り子の固定点を中心とした円
- 半径：`fieldRadius = min(canvas.width, canvas.height) × 0.42`
- 物理座標→画面座標スケール：`scale = fieldRadius / 振り子全長`
- サイズ：レスポンシブ（キャンバスはビューポートにフィット）

### 2.5 難易度システム

#### 2.5.1 ノーマルモード（**6プロファイル**：おもり数 × 階層）

UI 上は「振り子の数（2-bob / 3-bob）」のセグメントトグルと「Easy / Normal / Hard」のカード選択を組み合わせる。内部キーは `${bobs}-${tier}` 形式。

| キー | おもり数 | 長さ比率 | 初期角度ジッター |
|------|---------|---------|------------------|
| `2-easy`   | 2 | 1.0 : 0.8           | ±90° |
| `2-normal` | 2 | 1.0 : 0.6           | ±60° |
| `2-hard`   | 2 | 1.0 : 0.4           | ±45° |
| `3-easy`   | 3 | 1.0 : 0.8 : 0.6     | ±75° |
| `3-normal` | 3 | 1.0 : 0.7 : 0.5     | ±50° |
| `3-hard`   | 3 | 1.0 : 0.5 : 0.3     | ±35° |

- 角度の意味：鉛直下向きを `θ=0`、反時計回りを正とすると、鉛直上向きは `θ=π`（=180°）。各おもりの初期角度を「`π ± jitter`」の範囲で独立に一様乱数生成する
- 各プロファイルごとにハイスコア（TOP1）を localStorage で保存

#### 2.5.2 カスタムモード
- ユーザーが以下をすべて自由設定：
  - おもり数：2 または 3
  - 各おもりのロッド長
  - 各おもりの初期角度（直接指定）
- パラメータ調整中、振り子は静止（プレビュー）。`PREVIEW` トグルで動かして確認できる
- パラメータ調整 UI は以下の双方を提供（双方向同期）
  - **左パネル**：ロッド長スライダー（カスタムスタイル、ネイティブ不可）と初期角度ダイヤル
  - **右プレビュー上の直接操作**：おもりをドラッグで角度変更、ロッド端をドラッグで長さ変更
- ハイスコア：**保存対象**（`custom-2` / `custom-3` キー）。同じおもり数のカスタム間で TOP1 を共有
- カオス保証（2.6）は適用しない（ユーザー指定を尊重）

### 2.6 カオス保証（ノーマルモードのみ。**未実装、実装段階で追加**）
- 目的：難易度プロファイル範囲内で乱数生成された初期角度が、たまたまほぼ静止に近い動きにならないことを保証する
- 流れ：
  1. 難易度プロファイル範囲内で初期角度を一様乱数生成
  2. 数秒分の物理シミュレーションを実行
  3. 先端おもりの軌跡の総移動量を測定
  4. 閾値以下なら再生成、閾値以上なら採用
- 以下のパラメータは実装段階でチューニング：
  - 検証シミュレーション時間
  - 総移動量の閾値
  - 最大再試行回数（上限到達時は最後の生成結果を採用）

### 2.7 リトライ
- リトライ時は毎回新規ランダム生成（同一プロファイル内、別の初期角度）
- 同一シードでの再挑戦機能はなし
- リトライ起点：結果画面と一時停止メニューの双方から可能

### 2.8 軌跡表示
- 振り子先端おもりの過去の軌跡を画面に表示
- **直近 500ms** を保持し、線形に透明度をフェードアウト
- カスタム・ノーマル両モードで同様の表現
- 軌跡スタイルは `glow` で固定（Tweaks UI 非表示、2.13 参照）

### 2.9 リアルタイムフィードバック
- プレイ中、現在の距離スコアを視覚的にフィードバックする
- 既定：カーソルにロックオンリング（スコア上昇でリングが縮み、accent に発光）
- 補助：tether line（先端へのリーチライン）、vignette pulse（画面端の発光）
- 先端おもりは accent ringで強調、スコアに応じて glow が強まる

### 2.10 ハイスコア
- 永続化：localStorage（サーバー DB なし）
  - キー：`furiko-aim-highscores-v2`
  - 値：JSON `{ "<profileKey>": <score> }`
- 保存単位：プロファイルごと TOP1 のみ
- 対象：ノーマル6プロファイル＋カスタム（`custom-2`、`custom-3`）
- ユーザー名入力：なし
- 結果画面で新記録判定を表示
- 注意：ブラウザのストレージクリア・別端末・別ブラウザ・シークレットモードでは保持されない

### 2.11 開始前カウントダウン
- 開始時：**3 → 2 → 1 → GO** の 3 秒カウントダウン後にプレイ開始
- 一時停止からの RESUME 時も同じ 3 秒カウントダウン
- カウントダウン中はキャンバスを暗転・ぼかしせず、振り子と pivot を視認可能に保つ
- カウントダウン中は **「AIM HERE」マーカーが先端おもりを追従**（ユーザーが先端にカーソルを置いて開始準備できるように）
- 表示位置：カウントダウン数字は画面上部寄り、AIM HERE マーカーは先端位置

### 2.12 一時停止
- 操作：PAUSE ボタン または ESC / SPACE キー
- 一時停止中は物理時計と残時間を停止、軌跡もエージング停止
- RESUME 時は 3 秒カウントダウンを挟む（2.11）
- 一時停止オーバーレイの構成：
  - 上部：`PAUSED` kicker
  - その下：MODE 表示（accent 色、現在のプロファイル名）
  - 中段：TIME LEFT と SCORE の 2 ブロック
  - ボタン群：
    - **RESUME**：ゲーム再開（カウントダウンを挟む）
    - **RETRY**：同一プロファイルで新規ランダム生成して再挑戦
    - **DIFFICULTY**（カスタム時は **CUSTOM**）：難易度選択画面（カスタム時はカスタム設定画面）へ戻る
    - **HOME**：タイトル画面へ戻る（旧 ABORT を改名）

### 2.13 Tweaks パネル
- アクセント色 / 軌跡スタイル / フィードバック方式 / mono数字 / trail-scoring の切替を持つ調整パネル
- **本番では UI を非マウント（既定値固定、ユーザーからは見えない）**
- 既定値（固定）：
  - accent = `#d21e1e`
  - trailStyle = `glow`
  - feedbackStyle = `ring`
  - monoNumerics = `on`
  - trailScoring = `on`
- 実装ファイルとしては Tweaks 関連コードを残してもよいが、ルートにマウントしない

### 2.14 アクセント色
- **固定：`#d21e1e`（RGB 210, 30, 30、赤）**（2.13 で UI 非表示のため変更不可）

## 3. UI構造

### 3.1 画面遷移
```
タイトル
  ↓ START / Enter キー
モード選択（NORMAL / CUSTOM）  見出し：SELECT MODE
  ↓
[NORMAL] 難易度選択（2-bob/3-bob × Easy/Normal/Hard）  見出し：SELECT DIFFICULTY
[CUSTOM] パラメータ設定（おもり数・各長さ・各初期角度）
  ↓ START
カウントダウン（3-2-1-GO）
  ↓
ゲーム画面（60秒）
  ↓ 時間切れ / RETRY 経由
結果画面（スコア・新記録判定・RETRY / DIFFICULTY / TITLE / 保存・共有）
```

### 3.2 各画面の責務
- **タイトル**：ゲーム開始の入口（見出し「振り子エイム」、サブ「予測不能な振り子の軌跡を辿る」、START ボタン、Enter キー対応）
- **モード選択**：見出し `SELECT MODE`。NORMAL / CUSTOM の 2 カード
- **難易度選択**：見出し `SELECT DIFFICULTY`。kicker `NORMAL MODE`、おもり数セグメント（2 / 3）と Easy/Normal/Hard カード
  - 各カードに長さ比率・ジッター範囲・現在ハイスコアを表示
- **パラメータ設定**（カスタム時）：左にパラメータ欄（おもり数セレクタ・ロッド長スライダー・角度ダイヤル）、右にプレビュー（直接ドラッグでも調整可）。START は右プレビュー下部の独立 CTA
- **ゲーム画面**：振り子表示・カーソル追跡・HUD（2.15）・カウントダウンオーバーレイ・一時停止オーバーレイ
- **結果画面**：最終スコア・新記録判定（記録対象時）・PERFECT SCORE 比較・RETRY / DIFFICULTY / TITLE ボタン・保存・共有

### 3.3 カスタム画面の追加要件
- パラメータ変更中は振り子をシームレスに更新（点滅・再マウントなし）
- 左パネルの上下スクロールが必要な場合、**ネイティブの Web スクロールバーを使わずカスタムスタイル**で統一
- 既知バグ：3 おもりに切替後、初期角度を操作すると 2 おもりに戻る不具合あり。実装段階で修正

### 3.4 ゲーム画面 HUD レイアウト
- **左上**：PAUSE ボタン（`ESC` の kbd ラベル付き。SPACE も内部処理として有効だが UI 上の表記は ESC のみで省スペース化）
- **上中央**：残秒（数値、`TIME` ラベルなし）+ time-bar（数値の直下、コンパクト配置）
- **右上**：SCORE + PRECISION メーター（16 セル）+ % 表示
- **画面下**：（旧）ABORT を撤去。ABORT/HOME は一時停止メニューに集約
- MODE 表示は **HUD には載せず、一時停止オーバーレイ内に格納**（spec 2.12 の一時停止メニュー上部、PAUSED kicker の下）
- カウントダウン中は HUD を半透明化または通常表示のまま、`AIM HERE` マーカーで先端を強調

### 3.5 結果画面レイアウト
- 左：FINAL SCORE（大型数字）、新記録バッジ、難易度・ハイスコア・プレイ時間メタ、`RETRY / DIFFICULTY / TITLE` ボタン
- 右：PERFECT SCORE（6,000）、現スコアバー、`X% of perfect`
  - 右ブロックの数値サイズはハンドオフ準拠（`.result-stat .lg = 32px`）。視覚階層としてはサイドバー的に控えめに
- アクション：保存（スコア画面 PNG ダウンロード）、共有（Web Share API + Twitter intent フォールバック）

## 4. 物理シミュレーション仕様

### 4.1 座標系
- 振り子固定点を原点 `(0, 0)`
- 角度 `θ` は鉛直下向きを `0`、反時計回りを正
- 鉛直上向きは `θ = π`（=180°）

### 4.2 状態変数（n個のおもり）
- 角度：`θ_1, θ_2, ..., θ_n`
- 角速度：`ω_1, ω_2, ..., ω_n`

### 4.3 運動方程式
- n 振り子の標準的なラグランジアン形式から導かれる質量行列 `M(θ)` と RHS `b(θ, ω)` を毎ステップ構築し、`M α = b` をガウス消去で解いて角加速度 α を得る（n=2,3 で動作）
- 二重振り子に限定する場合は閉形式の式を使用してもよい

### 4.4 数値積分
- 手法：RK4（4次のルンゲ・クッタ法）
- 描画フレームレート：60fps
- 1描画フレームあたりの物理サブステップ数：8

### 4.5 物理パラメータ
- 質量：全おもり同一値（=1）
- 重力加速度：9.81
- ロッド長：難易度プロファイル または カスタム入力で決定
- 減衰：なし

## 5. 入力仕様
- 入力：マウスカーソル座標
- カーソルがフィールド外（円外）にある場合：3σ 以遠と同等で `score_per_frame = 0`
- キー操作：
  - `Enter`：タイトルから開始
  - `ESC`：ゲーム中に一時停止 / 再開
  - `Space`：ゲーム中に一時停止 / 再開
- タッチ操作：本仕様では非対応（PCマウス前提）

## 9. 用語定義
- **カオス振り子**：二重振り子または三重振り子
- **先端おもり**：固定点から最も遠い位置にあるおもり（ターゲット）
- **振り子全長**：すべてのロッド長の合計（先端おもりが固定点から到達できる最大距離）
- **σ（シグマ）**：先端追跡スコアの標準偏差。`σ = 振り子全長 × 0.06`
- **σ_t（トレイル σ）**：軌跡なぞりスコアの標準偏差。`σ_t = σ × 1.5`
- **許容半径**：`3σ`（または `3σ_t`）。これを超える距離ではスコアが 0
- **鉛直上向き**：`θ = π`（=180°）。固定点の真上方向
- **カオス保証**：乱数生成された初期角度が十分カオス的に動くことを、シミュレーション検証で担保すること
- **PERFECT SCORE**：理論最大スコア＝60秒 × 100 = 6,000
