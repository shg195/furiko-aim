## 要修正（仕様不適合）

### F-1. localStorage キーが仕様と異なる
- 該当: `src/constants.ts:53`
- 仕様: spec 2.10「キー：`furiko-aim-highscores-v2`」
- 実装: `HS_STORAGE_KEY = 'furiko-aim-highscores'`（`-v2` サフィックスが欠落）
- 影響: 永続化の鍵。仕様変更や移行戦略を考慮した命名なので一致させる必要あり
- 推奨対応: `'furiko-aim-highscores-v2'` に修正

### F-2. `vite.config.ts` に GitHub Pages 用 `base` 未設定
- 該当: `vite.config.ts`
- 仕様: spec 6「公開：GitHub Pages」、`docs/dev-guide-config.md` でも GitHub Pages 公開を明記
- 実装: `defineConfig({ plugins: [react()] })` のみ。`base` 指定なし
- 確認: `dist/index.html` の生成結果で `<script src="/assets/...">`、`<link href="/favicon.svg">` のように絶対パス。GitHub Pages のリポジトリ Pages（サブパス `/<repo>/`）にデプロイするとアセットが 404
- 推奨対応: `vite.config.ts` に `base: '/<repo-name>/'` を追加（リポジトリ名はユーザー確認）

### F-3. HUD の PAUSE ピルが ESC 表記のみ（SPACE 欠落）
- 該当: `src/components/HUD.tsx:58`
- 仕様: spec 3.4 / design.md 6.5「PAUSE ピル（ESC/SPACE 表記付き）」
- 実装: `<span className="kbd mono xs">ESC</span>` のみで `SPACE` の表記がない
- 推奨対応: `ESC` の隣に `SPACE` の kbd 表記を追加

### F-4. 結果画面の右ブロック数字が小さい（視覚階層が左 big-score と乖離）
- 該当: `src/styles/game.css:894`（`.result-stat .lg { font-size: 32px; }`）
- 仕様: spec 3.5「右側ブロックの数字サイズを左の big-score に視覚的に対等な階層に拡大」
- 実装: `.big-score` は `clamp(80px, 14vw, 180px)`、`.result-stat .lg` は 32px。明らかな乖離
- 補足: ハンドオフ `docs/design-handoff/project/styles.css:611` も 32px だが、`docs/design-handoff/README.md` で「結果画面サイズ」は spec.md 統合済みと明記。spec を優先すべき
- 推奨対応: `.result-stat .lg` を `clamp` で大きく（例：`clamp(56px, 9vw, 120px)` 程度）。実値はユーザー確認

### F-5. `index.html` の `<title>`・`lang` がテンプレ初期値のまま
- 該当: `index.html:2,7`、`dist/index.html` にも反映
- 実装: `<html lang="en">`、`<title>scaffold</title>`
- 推奨対応: `lang="ja"`、`<title>振り子エイム</title>`（または英訳併記）

## 要確認（仕様の解釈／ユーザー判断）

### Q-1. カスタムモード結果画面のメタ情報省略
- 該当: `src/screens/ResultScreen.tsx:90-118`
- 状況: カスタム時は `<div>難易度 CUSTOM</div>` のみで、ハイスコア・プレイ時間が非表示
- 仕様: spec 3.5「左：…難易度・ハイスコア・プレイ時間メタ」、spec 2.10 でカスタム（custom-2 / custom-3）はハイスコア保存対象
- 観察: 保存対象なのに表示しない理由が読み取れない
- 提案: カスタム時もハイスコア・プレイ時間を表示する／しないをユーザー判断

### Q-2. カスタムモードのリトライで初期角度が変わらない
- 該当: `src/App.tsx:46-69`（`runConfig` の useMemo）
- 状況: ノーマル時は `gameNonce` 変化で `generateChaoticAngles` 再呼び出しで角度再生成。カスタム時は `customCfg.angles` をそのまま使うので毎回同じ角度
- 仕様: spec 2.7「リトライ時は毎回新規ランダム生成（同一プロファイル内、別の初期角度）」
- 観察: spec 2.5.2 でカスタム角度はユーザー直接指定。spec 2.7 はノーマル前提とも読めるが明示なし
- 提案: 現状維持（ユーザー指定値を尊重）か、毎回ジッタ追加かをユーザー判断

## 要確認（規約・観察）

### Q-3. TypeScript の `strict` フラグが未設定
- 該当: `tsconfig.app.json`、`tsconfig.node.json`
- 規約: `docs/conventions.md` 6「Vite テンプレ既定の strict 設定をそのまま使う」
- 実装: `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch` のみで、`"strict": true` がない
- 補足: TypeScript 6.x / Vite 8.x 系の現行テンプレ既定で strict が外れたか、生成時に外したかは未確認。コード自体は any なし・暗黙 any なしで動作している
- 提案: `strict: true` の追加を検討（要修正かは規約解釈次第）

### O-1. `src/App.css` が未使用（観察）
- 状況: Vite テンプレの `.counter` / `.hero` / `#center` / `#next-steps` 等が残存。`main.tsx` でも `App.tsx` でも import されていない
- 影響: バンドルに含まれないので実害なし。ファイルとして残骸
- 提案: 削除可（ユーザーが明示許可した場合のみ）

### O-2. `README.md` が Vite テンプレートのまま（観察）
- 状況: プロジェクト固有のドキュメントなし
- 影響: 機能には無関係
- 提案: モジュール範囲外。気になる場合のみ書き換え

### O-3. `useGameLoop` の onFinish 依存と `App.finishGame` の参照不安定（観察）
- 該当: `src/hooks/useGameLoop.ts:80-99`、`src/App.tsx:71-89`
- 状況: `App.finishGame` が `useCallback` でラップされておらず、`useGameLoop` の useEffect 第2引数に `onFinish` が含まれているため、毎レンダーで raf 解除→再登録
- 影響: `finishedRef` でガードされているので機能上は無害。性能上の僅かな浪費
- 提案: `finishGame` を `useCallback` でラップ、または useGameLoop 側で onFinish を ref 化

### O-4. `CustomSlider` の useEffect 依存配列なし（観察）
- 該当: `src/components/CustomSlider.tsx:29-42`
- 状況: 毎レンダー window listener 再登録。`onChange` は closure 経由で参照される
- 影響: 機能は問題なし。性能上の僅かな浪費
- 提案: 依存配列追加または `onChangeRef` 化（AngleDial 同様）
